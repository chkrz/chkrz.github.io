LLM 已经在 Coding 领域被验证且取得了极大的成功。顺着这个逻辑，大家开始寻找下一个能够发生同样化学反应的领域，其中呼声最高、动作最密集的就是 Finance（金融）。

最近行业里动作频频：[Anthropic 高调发布了 Finance Agent 的应用和框架](https://www.anthropic.com/news/finance-agents)；此前也有消息传出，[OpenAI 招聘了大量银行家来帮助训练模型](https://www.afr.com/companies/financial-services/openai-hires-100-investment-bankers-to-train-its-ai-20251022-p5n4er)；国内的头部大模型公司也在火速跟进，推出了各种招募行业专家的 Fellow 计划。

但在这些热闹背后，我隐约有一种感觉：大家可能只是集体盯上了金融这块离钱最近的“肥肉”，但对于“具体要做什么”以及“这条路在底层逻辑上到底能不能走通”，依然是不清晰的。

## Coding 为什么行得通

我们先回过头看一个被验证过极度成功的场景：Coding。

现在大家都承认，LLM 写代码是真能打的，不是个噱头。很多人把这归结于代码数据多，或者模型本身变聪明了。但我觉得最核心的基石其实是：**Coding 是一个极其 well-defined 的任务。**

就像之前 AlphaProof、o1 在数学推理上的突破一样，能在 RL（强化学习）阶段起飞的方向，基本都符合两个前置条件：

首先，**得有个相对客观、且难以被 Hack 的指标 (Metric / Reward)**。
代码这东西，能跑通就是能跑通，过得了 Test Case 就是过得了。它是二元的，模型很难靠"装糊涂"蒙混过关。数学证明对不对，也有严格的形式化验证器说了算。这种天然干净的 Reward 是 RL 飞轮转起来的前提。

其次，**它得有一个现成、可低成本试错的测试环境 (Test Environment)**。
代码有解释器和可执行环境，你可以低成本地跑千百遍；数学有验证器。这意味着模型可以在环境里不断试错、获取反馈、迭代升级。这也是自动生成数据和开展评测的前提。

当这两个条件都凑齐，闭环才能打通，Scaling Law 才能在后训练阶段继续发力。

## 金融任务算 well-defined 吗？

顺着这个逻辑，我们把现在热炒的金融场景拆开来看看，它们符合这俩条件吗？

先说**投行（IBD）**。投行其实有大把的 Paper Work，像 Pitch Deck、尽职调查或者各种 Memo。这类工作本来就有固定的模板和叙事结构。用 LLM 来搞确实能提效，但这种活儿更像高级写作助手，而不是“智能决策”。更要命的是，这种任务没法定义清晰的 Metric。什么是“好”的 PPT？什么是“好”的摘要？最后都得靠 MD（董事总经理）主观拍板，根本没法自动化评估，自然也就做不了大规模的 RL 训练。

然后是**卖方研究（Sell-side Research）**。卖方的核心逻辑是消化巨大的信息量，梳理逻辑，最后抛出一个买、卖或持有的建议。乍一看，用股价涨跌当反馈不就行了吗？但现实是，研报逻辑对不对是一个非常主观和长期的判断。如果拿它推的标的未来一周的涨跌当 Metric，那这里面的宏观和情绪噪音实在太大了，短期完全无法验证模型的推理能力到底是好还是差。

那直接做**投资买方**（主观多头）呢？这类任务确实有很明确的 Metric，比如绝对收益、夏普比率。但它死在了第二个条件上：咱们很难建一个靠谱的 Test Environment。金融市场是一次性博弈，它不是一个能让你零成本反复重启跑 Agent 的沙盒。在所有的历史回测中搞 RL，模型最快学会的往往不是怎么赚钱，而是怎么 "Reward Hack"——用过拟合历史数据去骗过奖励函数。人类量化私募在防过拟合这事上已经焦头烂额了，强行把 LLM 丢进去并不能奇迹般解开这个死局。

## 唯一的例外：挖掘因子

不过我觉得在满地迷雾里，有一条窄路可能是通的：让 LLM 去量化框架里**挖 Alpha 因子**。

挖因子这个任务，出乎意料地完美契合了刚才说的两个条件。
首先，测试环境是现成的。各家量化机构本身就养着一套极其厚重的 Backtest 引擎，能算 IC、能算换手率，能直接拿来当 LLM 的 Environment。
其次，它的指标清晰且具有一定的反 Hack 属性。IC 和夏普是可以精确量化的。至于过拟合问题，量化界老早就建立了一套严苛的防线：重换手率惩罚、严格的 OOS（样本外）测试、Walk-forward 分析。这些规则虽然当初不是给 AI 准备的，但正好能限制住 LLM 搞小动作。

所以用 LLM 挖因子能通，不是因为它真的读懂了宏观经济或者看透了财报，而是因为“寻找统计规律并编写成可执行算子”这个任务，在现有的量化基建下，它刚好是个 well-defined 的工程问题。

## 写在最后

现在满大家都在问：能不能训出一个更懂金融的 LLM？
但我感觉这个发问的角度稍微有点偏了。不如先把眼光收回来问一句：**这个具体的金融任务，咱们把它 define 清楚了吗？**

如果是连人类自己都只能靠手感和经验的活儿，那 LLM 的天花板大抵也就是个高级提效工具，带不来什么能力边界的跃迁。

与其对着那些模糊的业务场景画大饼，不如去寻找下一个能形成闭环训练的、具备天然防作弊约束的“沙盒”。毕竟在代码和数学之外，能在现实世界里找到明确指标和测试环境的任务，真的已经不多了。
